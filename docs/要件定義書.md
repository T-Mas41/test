# 受領照合アプリ 要件定義書

| 項目 | 内容 |
|---|---|
| 版数 | 第1版(ドラフト) |
| 作成日 | 2026-11-25 |
| ステータス | ユーザー確認待ち(「11. 確認事項」への回答をもって確定) |

---

## 1. 目的

自社基幹システムから出力される **売上データ** と、得意先から受け取る **受領データ** を取り込み、
金額・数量・重量の一致/不一致を複数の切り口で一覧化する。差異を画面上で素早く特定し、
確認状況を記録し、Excel レポートとして出力できるようにする。

## 2. 前提・制約

| No | 内容 |
|---|---|
| 2-1 | 利用端末は Windows PC。利用者は1台のPC上で操作する(同時多人数利用は想定しない)。 |
| 2-2 | **アプリはローカル環境のみで動作し、社外へ一切通信しない。**(詳細は「9. 非機能要件」) |
| 2-3 | 自社売上データのレイアウトは1種類(基幹システム出力の Excel)。 |
| 2-4 | 受領データは「標準レイアウト」と、得意先ごとの「個別レイアウト」が複数存在する(Excel または CSV)。 |
| 2-5 | 商品コードは自社と得意先で異なるため、**販売台帳で必ず変換**してから照合する。 |
| 2-6 | 金額はすべて **税抜** で比較する。返品・値引きはマイナス金額で表現されている。 |
| 2-7 | 照合の一致判定は **完全一致**(1円・0.001kgでも差があれば差異)。許容誤差は設けない。 |

## 3. システム構成

| 項目 | 方式 |
|---|---|
| 形態 | ローカルWebアプリ(PC内でサーバーを起動し、同じPCのブラウザで操作) |
| 待受 | `127.0.0.1`(localhost)のみ。他PCからは接続不可 |
| 言語・基盤 | Python(Webフレームワーク: FastAPI)+ HTML/JavaScript |
| データ保存 | SQLite(PC内の1ファイル) |
| Excel入出力 | openpyxl |
| 配布形態 | exe化(PyInstaller)。利用PCへの Python インストールは不要 |
| 外部リソース | 画面で使う CSS/JavaScript/フォントはすべてアプリに同梱。CDN等のインターネット参照は行わない |

## 4. 業務フロー

```
[事前準備]
  ① 販売台帳を取込(随時・全件入替)
  ② 受領レイアウトを登録(サンプルファイルを取込 → 各項目の役割を設定)
  ③ 得意先(販売先)ごとに使用する受領レイアウトを割当(未割当は標準レイアウト)

[照合業務]
  ④ 照合を新規作成:販売先・期間(取引日付 From〜To)を指定
  ⑤ 売上データ(Excel)と受領データ(Excel/CSV)を取込
  ⑥ 照合実行 → 結果画面で差異を確認、確認済みチェック・コメントを記録
  ⑦ Excelレポートを出力

[履歴]
  ⑧ 過去の照合を一覧から開き、結果・確認状況を参照/再出力
```

## 5. 取込データ仕様

### 5-1. 自社売上データ(Excel / 固定レイアウト・188列)

- 1行目が見出し、2行目以降がデータ。
- 見出しに同名列が複数あるため(例:`販売先コード` がG列とEX列)、**列位置で項目を特定**する。
  取込時に、見出し名が想定と一致するかを検査し、不一致の場合はエラーとする。

| 用途 | 列 | 見出し名 | 備考 |
|---|---|---|---|
| 販売先コード | G (7) | 販売先コード | 照合対象の絞込に使用 |
| 販売先名 | H (8) | 販売先略称 | 表示用 |
| 店舗コード | CC (81) | 店舗コード | |
| 店舗名 | CD (82) | 店舗略称 | 表示用 |
| 取引日付 | EG (137) | 取引日付 | `YYYYMMDD` |
| 相手先注文番号 | AI (35) | 相手先注文番号 | 伝票照合キー |
| 商品コード | I (9) | 商品コード | 自社商品コード |
| 商品名 | J (10) | 商品略称 | 表示用 |
| 数量 | AG (33) | 売上数量 | |
| 重量 | AF (32) | 重量(kg) | |
| 金額 | BF (58) | 即引後売上金額 | 税抜 |
| (参考)売上伝票番号 | R (18) | 売上伝票番号(連番) | 明細表示用 |

- 取り込んだファイルのうち、照合で指定した **販売先コード** と **取引日付の期間** に該当する行だけを対象にする。
- 取込除外条件(売上伝票状態区分 など)は「11. 確認事項 Q1」で確定する。

### 5-2. 受領データ

受領データは「受領レイアウトマスタ」(6-2)の定義に従って読み込み、次の **共通項目** に変換する。

| 共通項目(役割) | 必須 | 説明 |
|---|---|---|
| 取引日付 | ○ | 日別照合に使用 |
| 相手先注文番号 | ○ | 伝票照合キー |
| 相手先商品コード | ○ | 販売台帳で自社商品コードに変換 |
| 金額 | ○ | 税抜 |
| 数量 | | |
| 重量 | | |
| 店舗コード | | 日別店別の照合に使用 |
| 販売先コード | | ファイルにない場合は、照合作成時に指定した販売先を使う |
| 商品名 | | 表示用 |
| 単価 | | 表示用 |
| 未使用 | | 照合に使わない |

#### データ変換ルール

| 対象 | ルール |
|---|---|
| 日付 | `YYYYMMDD` / `YYYY/MM/DD` / `YYYY-MM-DD` / Excelの日付型 を自動判別。レイアウトごとに書式を指定することもできる |
| 数値 | カンマを除去。空欄は0。マイナス記号はそのまま扱う |

### 5-3. 販売台帳(Excel / 固定レイアウト・211列)

| 用途 | 列 | 見出し名 |
|---|---|---|
| 削除区分 | A (1) | 削除区分(`9` = 削除 → 取込対象外) |
| 自社商品コード | BG (59) | 商品コード |
| 商品名 | BH (60) | 商品略称 |
| 相手先商品コード | BT (72) | 販売先商品識別ｺｰﾄﾞ |
| 販売先コード | DG (111) | 販売先コード |
| 店舗コード | DI (113) | 店舗コード(`99999999999` = 指定なし) |

- 取り込むたびに **全件入れ替え** とする。
- 適用期間(適用開始日・適用終了日)は考慮しない。

## 6. マスタ仕様

### 6-1. 販売台帳マスタ
5-3 の項目を保持する。取込日時と件数を画面に表示する。

### 6-2. 受領レイアウトマスタ

| 項目 | 内容 |
|---|---|
| レイアウト名 | 任意の名称 |
| 標準フラグ | 1つだけ「標準」に指定できる。得意先に割当がない場合はこれを使う |
| ファイル形式 | Excel / CSV |
| 文字コード(CSV) | Shift_JIS(CP932) / UTF-8 / UTF-8(BOM付) |
| 区切り文字(CSV) | カンマ / タブ |
| シート指定(Excel) | 先頭シート または シート名 |
| 見出し行 | 何行目か(既定 1) |
| データ開始行 | 何行目か(既定 2) |
| 項目定義 | 列番号・見出し名・役割(5-2の共通項目)・日付書式(任意) |

**登録の流れ**:サンプルファイルを取り込むと、見出し行から列の一覧(列番号・見出し名・先頭数行の値)が自動で作られる。
利用者は各列の「役割」をプルダウンで選んで保存する。必須の役割が未設定の場合は保存できない。

### 6-3. 得意先レイアウト割当マスタ

| 項目 | 内容 |
|---|---|
| 販売先コード | 得意先(自社の販売先コード) |
| 販売先名 | 表示用 |
| レイアウト | 6-2 のレイアウト |

割当がない販売先は標準レイアウトを使う。

## 7. 照合仕様

### 7-1. 受領データの商品コード変換

受領の各行について、販売台帳(削除区分≠9)を次の順で検索し、自社商品コードを決める。

1. 販売先コード + 店舗コード + 相手先商品コード(=販売先商品識別ｺｰﾄﾞ)で一致
2. 1で見つからなければ、販売先コード + 店舗コード`99999999999`(指定なし)+ 相手先商品コード ※確認事項 Q5
3. 結果の扱い

| 結果 | 扱い |
|---|---|
| 1件ヒット | 変換する |
| 複数件ヒット | **警告**を出し、最初にヒットした行(台帳の取込順で先頭)を採用する |
| ヒットなし | **変換不可**とし、相手先商品コードの頭に `[未変換]` を付けたコードで照合を続ける(結果は必ず不一致になる)。変換不可の一覧に出す |

### 7-2. 照合の切り口

各切り口で、売上・受領のそれぞれを集計キーごとに合計し、突き合わせる。

| No | 切り口 | 集計キー |
|---|---|---|
| 1 | 合計 | (なし。全体の合計) |
| 2 | 日別 | 取引日付 |
| 3 | 日別店別 | 取引日付 + 店舗コード |
| 4 | 伝票番号別 | 相手先注文番号 |
| 5 | 日別商品別 | 取引日付 + 自社商品コード |

### 7-3. 比較項目と判定

- 比較項目:**金額・数量・重量**(3つすべてを並べて表示)
- 差異 = 売上 − 受領

| 判定 | 条件 |
|---|---|
| 一致 | 両方に存在し、金額・数量・重量がすべて同じ |
| 差異あり | 両方に存在し、いずれかが違う(違う項目を「金額」「数量」「重量」と表示) |
| 自社のみ | 売上にだけ存在する |
| 受領のみ | 受領にだけ存在する |

- 数値の比較は、金額は整数、数量・重量は小数第3位まで(第4位で四捨五入)で行う。※確認事項 Q6

### 7-4. 確認状況の記録

- 各切り口の結果行ごとに **「確認済み」チェック** と **コメント**(自由入力)を記録できる。
- 記録には更新日時を残す。
- 同じ照合で再取込・再照合をしても、キーが同じ行の確認状況は引き継ぐ。

## 9. 非機能要件

### 9-1. 情報漏洩対策(最重要)

| No | 対策 |
|---|---|
| 9-1-1 | サーバーは `127.0.0.1` にのみ待ち受ける。LAN内の他PCからもアクセスできない |
| 9-1-2 | アプリから外部へ通信する処理を一切持たない(更新確認・利用統計・エラー送信なし) |
| 9-1-3 | 画面の CSS/JavaScript/フォントはすべて同梱し、外部の CDN を参照しない |
| 9-1-4 | データ(DB・取込ファイルの写し・出力レポート)は、アプリのフォルダ配下のローカルディスクにだけ保存する |
| 9-1-5 | ログに金額・取引先名などの業務データを出力しない(件数・エラー種別のみ) |

### 9-2. その他

| 項目 | 要件 |
|---|---|
| 性能 | 売上・受領それぞれ数万行(目安:各5万行)で、取込から照合完了まで1分以内 ※確認事項 Q7 |
| 操作性 | 利用者はExcelに慣れた事務担当者を想定。ファイル選択はドラッグ&ドロップにも対応 |
| バックアップ | DBは1ファイルのため、フォルダのコピーでバックアップ・移行できる |
| エラー処理 | 取込エラーは行番号と理由を画面に表示し、エラー行を除いて続けるか中止するかを選べる |

## 10. Excelレポート仕様

ファイル名:`受領照合_{販売先コード}_{期間From}-{期間To}_{出力日時}.xlsx`

| シート | 内容 |
|---|---|
| サマリ | 照合条件(販売先・期間・取込ファイル名・取込件数)、合計の売上/受領/差異、切り口ごとの判定件数 |
| 日別 | 7-2 No.2 の結果 |
| 日別店別 | 7-2 No.3 の結果 |
| 伝票別 | 7-2 No.4 の結果 |
| 日別商品別 | 7-2 No.5 の結果 |
| 変換警告 | 変換不可・複数ヒットの受領明細 |

- 各結果シートの列:キー項目/売上(金額・数量・重量)/受領(金額・数量・重量)/差異(金額・数量・重量)/判定/確認済み/コメント
- 判定が一致以外の行は背景色を付ける(差異あり:黄、自社のみ:青、受領のみ:赤)。
- 見出し行の固定、オートフィルタの設定、数値の桁区切りを行う。

## 11. 確認事項(未確定)

以下は仮の内容で本書に反映済みです。違う場合はご指摘ください。

| No | 内容 | 仮の決定 |
|---|---|---|
| Q1 | 売上データから **除外すべき行** はあるか(取消伝票、売上伝票状態区分が未確定、サンプル出荷など) | 除外なし(全行を対象) |
| Q2 | 標準レイアウトの数量に使う列。「受領数量」(F列)と「受領数量(総バラ)」(U列)のどちらか | 受領数量(総バラ) |
| Q3 | 流通BMS形式CSVの割当:取引日付=計上日、店舗=最終納品先コード、商品コード=商品コード(発注用)、金額=原価金額 でよいか | 左記のとおり(画面で変更可) |
| Q4 | 相手先注文番号・コード類の **先頭ゼロ**(例 `0007227151` と `7227151`)は同一とみなすか | 同一とみなす(先頭ゼロを除いて比較) |
| Q5 | 販売台帳で、店舗コード完全一致が無いとき「指定なし(99999999999)」の行で代用してよいか | 代用する |
| Q6 | 数量・重量の比較精度(小数第3位まで)でよいか | 小数第3位まで |
| Q7 | 1回の照合あたりの行数の目安(売上・受領それぞれ) | 各5万行以内 |
| Q8 | 伝票番号別の照合で、同じ相手先注文番号が別の日付・店舗にまたがることはあるか | ない(相手先注文番号だけをキーとする) |

# 議事録作成スキル

文字起こしTXTを取り込み、4つのフェーズを**順番に・ユーザー確認を挟みながら**進める。
文字列の置換・検証・Word生成は必ず `scripts/` のスクリプトで行い、AIが全文を書き写して出力しない（本文改変の防止）。
スクリプトは `python3 <このスキルのパス>/scripts/xxx.py` で実行する。作業ファイルは入力ファイルと同じ場所に出力する。

## 全体ルール
- 他の会議データ・過去の会話から情報を補完しない。推測は確定扱いせず、必ずユーザーに確認する。
- 各フェーズの完了時に成果物のパスと要点を提示し、承認を得てから次へ進む。
- 質問はまとめて1回で行い、ユーザーが答えやすい番号付きリストにする。

## フェーズ0: 取り込み
最初にユーザーへ「会議の文字起こしTXTファイルを添付(またはパス指定)してください」と促す。受領後、UTF-8で読めるか・発言者ラベルの書式（例: `参加者1 00:01:25` + 次行から本文）を確認する。
書式が標準と異なる場合は、各スクリプトの `--pattern` にラベル行の正規表現を渡す（名前付きグループ `label` 必須）。

## フェーズ1: 発言者名の確定
目的: 発言者ラベルだけを正しい氏名(部署名)に置換する。**議事録作成や要約はここでは行わない。**

1. `extract_speakers.py 入力.txt` を実行し、発言者ごとの発言数・初出時刻・発言抜粋(原文のまま)をJSONで得る。
2. 文字起こし全文（デモ動画のナレーションも含む）から、呼びかけ・自己紹介・所属・役職・発言内容を根拠に氏名/所属を推測する。推測不能は「不明」。
3. 発言者ごとに以下を一覧提示してユーザーに質問する:
   - 発言者識別名 / 予測される氏名・会社名・部署名 / 推測の根拠 / 発言抜粋(原文2〜3件) / 発言時刻
   - 例: `参加者1 ／ 予測：山田氏（ABC社 営業部）／ 根拠：自社サービスを説明 ／ 発言例：「本日は弊社の…」 ／ 氏名・所属は正しいですか？`
4. 未確認の発言者がいれば追加質問。「不明のままでよい」は元の識別名を維持。
5. 確定した対応を `speaker_map.json`（`{"参加者1": "山田氏（ABC社 営業部）"}`）に保存し、実行:
   `apply_speakers.py 入力.txt speaker_map.json`
   → `元ファイル名_発言者名修正版.txt` を出力。スクリプトが元データと比較し、**ラベル行以外が1文字も変わっていないこと**、発言数・順序・タイムスタンプ・置換漏れを自動検証する。検証NGなら原因を報告し、出力を提示しない。
6. 提示するもの: 出力ファイルのパス、発言者の修正対応表、検証結果。出力ファイルには全文のみを入れ、説明文・対応表を混ぜない。
   本文中の参加者番号や人名は変更しない（スクリプトは触らない）。

## フェーズ2: 固有名詞の表記修正
1. フェーズ1の出力ファイルから固有名詞（会社名・製品/サービス名・人名・部署名・プロジェクト名・専門用語・略語）を抽出する。`extract_terms.py` が頻出する漢字/カタカナ/英字の語の候補を出すので、それを参考にAIが全文を確認して補う。
2. 「表記ゆれ・誤変換の疑い」を併記した一覧（語／出現回数／疑いの有無／想定される正しい表記）をユーザーに提示する。
3. ユーザーから修正指示（例: `エービーシー→ABC`）を受け取り、`terms_map.json` にして実行:
   `apply_terms.py 発言者名修正版.txt terms_map.json`
   → `元ファイル名_固有名詞修正版.txt` を出力。語ごとの置換件数を報告する（0件の指示は報告して確認）。発言者ラベル行は置換対象外。
4. 追加の修正指示があれば繰り返す。「修正なし」ならスキップ可。

## フェーズ3: 議事録(Word)作成
1. **前回議事録の確認**: 「前回の議事録を添付してください。ない場合は『なし』とお答えください」と問いかける。添付があれば「次回までの宿題」を読み取る。「なし」なら 2.に「前回宿題無し」と記載。
2. **ひな形の確認**: ユーザーがひな形(.docx)を添付した場合はその構成・書式を最優先で踏襲する。無ければ `references/format_spec.md` の既定仕様を使う。
3. 文字起こしから `minutes.json`（`references/minutes_schema.md`）を作成する。作成ルール:
   - 見出し番号・見出し名・表の項目名は変更・省略しない。
   - 確定できない情報（氏名・担当者・期限・日時・場所・開催形式など）は推測で断定せず「要確認」または「未定」。
   - 発言から推定した内容には「（発言から推定）」を付ける。文字起こしに無い内容は追加しない。
   - 概要は5行程度（1文ずつ）。議事内容は時系列で議題ごとの小見出し（目安経過時間可）。
4. **不明点の質問**: `minutes.json` 内の「要確認」「未定」項目（開催日時・会議名・開催形式/場所・出席者/欠席者・担当者・期限・次回会議日時 等）を一覧にし、ユーザーへまとめて質問する。回答を反映してから出力する。
5. `build_minutes.py minutes.json 議事録.docx` で出力（ヘッダーにページ番号、メイリオ・本文11pt、基本情報と宿題は表形式、宿題表は連番列が最狭・対応事項列が最広）。
6. 提示: docxのパス、作成の前提（文字起こし基準・固有名詞/時刻は要確認）、残っている要確認箇所。修正依頼があれば `minutes.json` を直して再生成する。

最後に必ず注記を文書末尾に1〜2行入れる（`note` フィールド。省略時はスクリプトが既定文を入れる）。

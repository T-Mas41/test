# 受領照合アプリ

自社の売上データ(基幹システム出力のExcel)と、得意先からの受領データ(Excel / CSV)を取り込んで照合し、
差異を画面で確認・記録し、Excelレポートに出力するローカル専用アプリです。

- 要件定義書:[docs/要件定義書.md](docs/要件定義書.md)
- 画面デザイン:A案(スタンダード:左メニュー・カード型)

## 情報漏洩対策

| 対策 | 実装 |
|---|---|
| 他PCから接続できない | `127.0.0.1` だけで待ち受け(変更する設定なし)。Host ヘッダーも `127.0.0.1` / `localhost` 以外は拒否 |
| 外部へ通信しない | 外部通信を行う処理なし。画面の CSS / JavaScript は同梱し、CSP(`default-src 'self'`)でブラウザからの外部読込も禁止 |
| 自動生成のAPIドキュメント画面 | 外部CDNを参照するため無効化(`/docs` などは表示されない) |
| データの保存先 | アプリのフォルダ内 `data\app.db`(SQLite の1ファイル)のみ |
| ログ | アクセスログを出力しない(URL内の伝票番号などを残さない) |

## 使い方(Windows)

### exe を作る(初回のみ・開発担当者)

1. Python 3.11 以上をインストール
2. このフォルダで `build_exe.bat` を実行(依存ライブラリの取得・テスト・exe 作成)
3. `dist\ReceiptMatcher` フォルダが完成品です。フォルダごと利用者のPCにコピーします

> ライブラリの取得時のみインターネット(PyPI)に接続します。完成した exe は通信しません。

### 起動・終了

- `ReceiptMatcher.exe` をダブルクリック → ブラウザで画面が開きます(`http://127.0.0.1:8765/`)
- 終了するときは、黒いウィンドウを閉じます
- Python がある環境では `start_from_source.bat` でも起動できます

### 業務の流れ

1. **販売台帳**:基幹システムの販売台帳(Excel)を取り込む(全件入れ替え・削除区分9は除外)
2. **受領レイアウト・得意先割当**:得意先独自の形式があれば、サンプルファイルから登録して役割(取引日付・相手先注文番号・相手先商品コード・金額など)を設定し、販売先に割り当てる。割当のない販売先は「標準」レイアウトで読み込む
3. **新規照合**:販売先・期間を指定し、売上データと受領データを取り込む → 取込件数・エラー・変換警告を確認して実行
4. **照合結果**:日別/日別店別/伝票番号別/日別商品別/変換警告で差異を確認。確認済みチェック・コメントは自動保存
5. **Excelレポート出力**:サマリ・各切り口・変換警告のシートを出力

### バックアップ・移行

`data` フォルダをコピーするだけです(アプリを終了してから行ってください)。

## 照合ルール(要点)

- 金額は税抜の「即引後売上金額」と「受領金額」を整数で比較。数量・重量は小数第3位まで比較。許容誤差なし
- 相手先注文番号・コード類は前後の空白と先頭ゼロを除いて比較(`0007227151` と `7227151` は同じ)
- 受領の相手先商品コードは販売台帳で自社商品コードに変換(①販売先+店舗+コード → ②販売先+店舗「指定なし」+コード)。複数候補は先頭を採用して警告、該当なしは `[未変換]` を付けて照合
- 売上データの列は位置で特定し、取込時に見出し名を検査(基幹システムのレイアウトが変わった場合はエラーで知らせる)

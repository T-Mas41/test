# 受領照合アプリ

自社の売上データ(基幹システム出力のExcel)と、得意先からの受領データ(Excel / CSV)を取り込んで照合し、
差異を画面で確認・記録し、Excelレポートに出力するアプリです。

**`受領照合.html` をダブルクリックして、Microsoft Edge か Google Chrome で開くだけで動きます。**
インストール・Python・exe は不要です。

- 要件定義書:[docs/要件定義書.md](docs/要件定義書.md)
- 画面デザイン:白いサイドメニュー+紫グラデーションのカード型(2026-11-27 変更)

## 使い始め方

1. `受領照合.html` を、PCのわかりやすい場所(例:`C:\受領照合\`)に保存します
2. ダブルクリックして開きます(既定のブラウザが Edge / Chrome 以外の場合は、右クリック →「プログラムから開く」→ Edge)
3. ブラウザのお気に入り(ブックマーク)に登録しておくと、次回から簡単に開けます

> InPrivate / シークレットウィンドウでは使えません(データを保存できないため)。通常のウィンドウで開いてください。

## 業務の流れ

1. **販売台帳**:基幹システムの販売台帳(Excel)を取り込む(全件入れ替え・削除区分9は除外)
2. **受領レイアウト・得意先割当**:得意先独自の形式があれば、サンプルファイルから登録して各列の役割
   (取引日付・相手先注文番号・相手先商品コード・金額など)を設定し、販売先に割り当てる。割当のない販売先は「標準」レイアウト
3. **新規照合**:期間を指定し、売上データと受領データを取り込む(販売先は売上データから自動判定。複数の販売先が混ざっているとエラー)→ 取込件数・エラー・変換警告を確認して実行
4. **照合結果**:日別/日別店別/伝票番号別/日別商品別/変換警告で差異を確認。確認済みチェック・コメントは自動保存
5. **Excelレポート出力**:保存先を選ぶ画面が出るので、保存場所を指定する
6. **バックアップ・復元**:定期的にバックアップファイルを保存する(下記)

## データの保存とバックアップ(重要)

- データは **そのPCのブラウザ内(IndexedDB)** に保存され、PCの外には出ません
- ブラウザの「閲覧データの削除」で **Cookieとサイトデータ** を消すとデータも消えます。
  「バックアップ・復元」画面から、定期的にバックアップファイル(.json)を保存してください
- 別のPCへ移すときも、バックアップ → 別PCで復元 で移せます
- データは「Edge」「Chrome」などブラウザごと・Windowsユーザーごとに別々です(毎回同じブラウザで開いてください)

## 情報漏洩対策

| 対策 | 実装 |
|---|---|
| 外部へ通信しない | 通信処理なし。さらに CSP(`connect-src 'none'` など)でブラウザ側からも通信・外部ファイル読込を禁止 |
| 外部のプログラムを使わない | Excel・CSVの読み書きも含め、すべてこのHTMLファイル内の自作コード(外部ライブラリ・CDN不使用) |
| データの保存先 | このPCのブラウザ内のみ。取り込んだファイルはブラウザの中で読むだけで、どこにも送らない |

## 照合ルール(要点)

- 金額は税抜の「即引後売上金額」と「受領金額」を整数で比較。日別・日別店別・伝票番号別は金額のみ、日別商品別は数量・重量・金額を比較(小数第3位まで)。許容誤差なし
- 相手先注文番号・コード類は前後の空白と先頭ゼロを除いて比較(`0007227151` と `7227151` は同じ)
- 自社商品コードは「商品識別コード」(9桁)。受領の相手先商品コードは販売台帳で自社商品コードに変換(①販売先+店舗+コード → ②販売先+店舗「指定なし」+コード)。
  複数候補は先頭を採用して警告、該当なしは `[未変換]` を付けて照合
- 売上データの列は位置で特定し、取込時に見出し名を検査(基幹システムのレイアウトが変わった場合はエラーで知らせる)

## 開発者向け

- ソース:`html_app/src/`(`js/10_files.js` Excel/CSV読書き、`40_logic.js` 照合ロジック、`90_ui.js` 画面、`style.css`)
- ビルド(ソースから `受領照合.html` を作る):

```bash
python3 tools/build_html.py
```

- テスト(Node.js 22以上。架空データは `python tools/make_demo_files.py demo_files` で作成):

```bash
node html_app/test/run_tests.mjs demo_files
```

- `receipt_matcher/` は以前のサーバー版(Python)です。2026-11-27 以降の仕様変更(識別コード9桁・販売先の自動判定など)は反映していません。テスト用の架空データ生成に使っています。
- 実データ・実サンプルはリポジトリに入れないでください
